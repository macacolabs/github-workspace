Git 준비도 평가

안내된 명령 순서 없이 Issue부터 기능 브랜치, 커밋, PR 리뷰, 충돌 해결, 병합까지 독립 수행합니다.

종합평가최소 안내실제 PR

명령 전에 내부 상태 읽기

restore --staged는 커밋 후보를 바꾸고 작업 파일을 남깁니다. 일반 restore는 작업 파일 내용을 복원합니다. reset의 커밋 지정 형식은 현재 브랜치의 위치를 이동하며 모드에 따라 index와 작업 트리도 바꿉니다. soft가 파일을 남겨도 공유 이력 변경까지 안전한 것은 아닙니다.

상세 원리·복구 방법 선택·검증 연습 →

평가 목표

명령 목록을 그대로 따라 하는 평가가 아닙니다. 요구사항을 읽고 필요한 Git 흐름을 스스로 선택해 팀 작업을 완료합니다.

평가 중 금지

다른 학생의 명령을 그대로 복사하거나 위험 명령을 승인 없이 실행하면 중단 후 재평가합니다. 도움을 요청할 수 있지만 상태 근거를 포함해야 합니다.

프로젝트 요구사항

team-profile 프로젝트에 “팀 연락 방법” 기능을 추가합니다.

  • Issue에 목적과 완료조건 작성
  • 최신 main에서 기능 브랜치 생성
  • members/자기이름.md 수정
  • team.md 문서에 연락 안내 추가
  • 목표 문서와 소개 문서 변경을 목적별 커밋으로 분리
  • Markdown 내용·누락·충돌 표시 검증
  • 기능 브랜치 push와 PR
  • 동료의 구체적인 리뷰 1개 이상
  • 리뷰를 새 커밋으로 반영
  • 의도적인 같은 줄 충돌 해결
  • 병합 후 로컬 main 최신화

Explain Gate

강사는 아래 중 임의의 질문을 선택합니다. 명령 이름만 말하지 않고 상태 변화와 팀 영향을 설명해야 합니다.

  1. 현재 로컬 브랜치와 원격 추적 브랜치는 무엇이 다른가?
  2. 이번 커밋에 포함된 변경을 어떤 근거로 확인했는가?
  3. push가 거절되면 가장 먼저 무엇을 확인하는가?
  4. 충돌에서 어떤 내용을 남겼고 왜 그렇게 결정했는가?
  5. revert와 reset 중 공유 이력에 적합한 선택은 무엇이며 왜 그런가?
  6. 비밀정보가 원격에 올라갔다면 왜 파일 삭제만으로 부족한가?
  7. 다음 프로젝트 작업을 시작할 때 첫 세 단계는 무엇인가?

판정

정상 흐름 평가 후 조건을 바꾼 복합 문제에서도 보존·판단·복구를 확인합니다. 같은 명령을 외워 반복한 것만으로 독립 수행을 인정하지 않습니다.

결과조건
PASS필수 수행 전체, 데이터 손실 없음, Explain Gate 통과
재실습한 단계 힌트 후 안전하게 복구했지만 독립 수행 부족
재평가main 직접 push, force push, 비밀정보 노출, 타인 변경 무단 삭제, 상태 설명 불가

프로젝트 투입 기준

이 평가 PASS 후에도 실제 프로젝트 첫 3회 작업을 동일 기준으로 반복합니다. 3회 연속 독립 수행해야 프로젝트 Git 독립 수행 PASS입니다.
