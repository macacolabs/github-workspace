개정 내용·공통 진단·보존·중단·검증 안내 보기 — 연습 전에 준비 환경과 현재 위치를 확인하세요.

파일은 하나인데 왜 상태는 두 개일까?

README를 수정하고 add한 뒤 다시 수정했습니다. 지금 commit하면 화면에서 보이는 최신 내용이 모두 저장될까요? add는 파일 이름을 예약하는 것이 아니라 그 시점의 내용을 index에 반영합니다.

내부 원리실습검증

내부에서는 어떤 일이 일어날까?

Git은 파일 내용(blob), 디렉터리 구조(tree), 부모 커밋과 작성 정보가 있는 commit 객체로 스냅샷을 표현합니다. 파일 내용이 같으면 기존 객체를 재사용할 수 있습니다. 커밋은 매번 전체 폴더를 별도 복사하는 방식이 아닙니다.

작업 트리는 편집기에서 보는 파일입니다. index는 다음 커밋에 담을 경로와 내용의 목록입니다. HEAD가 가리키는 커밋은 마지막으로 기록된 기준입니다. status는 이 세 상태 사이 차이를 요약합니다.

git diff는 작업 트리와 index를, git diff --staged는 index와 HEAD를 비교합니다. 파일이 MM으로 보이면 첫 M은 stage된 수정, 둘째 M은 add 이후의 추가 수정입니다. commit은 index를 기록하므로 둘째 수정은 자동 포함되지 않습니다.

1. 시작 상태 만들기

아래 명령은 새 연습 폴더에서 Markdown 파일로 상황을 직접 만듭니다. PowerShell에서 한 줄씩 실행하세요. Set-Content는 파일을 덮어쓰므로 기존 프로젝트에서 실행하지 않습니다. 예상 오류 외의 실패가 나오면 중단합니다. 전체 직접 실습 MD 다운로드

# Windows PowerShell. 한 줄씩 실행하고 실패하면 멈춥니다.
$practiceRoot = Join-Path ([IO.Path]::GetTempPath()) ("git-md-" + [guid]::NewGuid())
New-Item -ItemType Directory -Path $practiceRoot -ErrorAction Stop
Set-Location $practiceRoot
git init -b main
git config user.name "Practice Student"
git config user.email "practice@example.invalid"
# 아래 설정은 이 새 연습 저장소에만 적용합니다.
git config commit.gpgsign false
git config core.autocrlf false
git config core.whitespace cr-at-eol
git config core.hooksPath .no-hooks
Set-Content README.md "team=base"
Set-Content notes.md "note=base"
git add README.md notes.md
git commit -m "docs: base"
git status --short

Set-Content README.md "team=profile"
git add README.md
Set-Content README.md "team=profile-v2"
Set-Content notes.md "note=unrelated"
git add notes.md
Set-Content draft.md "draft=keep"
git status --short

README는 MM, notes는 M의 첫 열, draft는 ??로 보입니다. README의 두 diff를 비교해 profile과 profile-v2가 어느 영역에 있는지 찾습니다.

2. 진단하고 예상하기

git status --short
git diff -- README.md
git diff --staged -- README.md
git diff --staged -- notes.md

명령 실행 전 어떤 파일·참조가 달라질지 말하고, 실행 후 출력과 비교합니다.

3. 복구 방법 선택

README 최신 내용만 커밋하고 notes와 draft는 보존해야 합니다. notes를 작업 파일에서 삭제하거나 restore로 버리는 것은 목표와 다릅니다. stage에서만 빼야 합니다.

판단 후 복구 절차 펼치기
git restore --staged notes.md
git add README.md
git diff --staged
git commit -m "docs: update team profile"

4. 복구 성공을 검증하기

git show --stat HEAD
git status --short
Get-Content notes.md
Get-Content draft.md

새 커밋에는 README만 포함됩니다. README는 profile-v2, notes는 unrelated, draft는 keep 내용이 남아야 합니다. 전체 작업 트리가 clean이 아니어도 정상입니다. 보존한 다른 작업이 남아 있기 때문입니다.

멈춰야 할 경계

restore 파일명은 기본적으로 index의 내용을 작업 파일에 복원합니다. add하지 않은 변경을 버릴 수 있으므로 stage 해제와 혼동하지 않습니다.

5. 조건을 바꿔 설명하기

README도 첫 번째 수정만 커밋해야 한다면 다시 add해야 할까요? 파일 일부만 분리할 때는 git add -p로 각 변경 덩어리를 읽고 선택하는 연습으로 확장합니다.

제출할 문서는 없습니다. 화면에서 근거를 가리키며 “현재 상태 → 선택 이유 → 남은 작업”을 설명합니다.

공식 문서와 연결

Git add 공식 문서에서 명령의 입력·출력 범위를 확인합니다. 예제는 PowerShell 기준입니다. 실제 해시·브랜치명은 출력에서 확인하며 그대로 추측해서 입력하지 않습니다.
