조건이 달라도 혼자 해결할 수 있을까?

정답 순서를 기억했는지가 아니라, 처음 보는 상태에서 보존·선택·검증을 수행하는지 확인합니다. 제출 입력란이나 별도 제출물은 없습니다.

첫 단계: 안내를 줄이기

  1. 첫 연습은 원리와 그림을 읽고 복구 절차를 펼쳐 수행합니다.
  2. 다음 연습은 절차를 닫고 상태 확인 명령만 참고합니다.
  3. 마지막 연습은 아래 요구사항만 읽고 진단부터 스스로 수행합니다.

복합 문제 A · 다른 PC에서 이어서 작업

remote 모드를 생성합니다. 내 커밋도 있고 동료의 커밋도 있으며 notes에는 미완성 작업이 있습니다. 목표는 양쪽 커밋을 통합해 원격에 반영하되 미완성 notes는 원격에 올리지 않고 현재 PC에 남기는 것입니다.

  • origin/main의 정보가 최신인지 어떻게 확인할까요?
  • 미완성 notes와 내 커밋은 같은 방법으로 보존해야 할까요?
  • 완료 후 clean이어야 할까요, 변경이 남아야 할까요?

복합 문제 B · 잘못된 브랜치와 긴급 전환

branch 모드를 생성합니다. feature에 미완성 README 변경이 있고 main으로 전환하면 거절됩니다. main에서 기준 내용을 확인한 뒤 돌아와 작업을 그대로 이어가세요. 별도 파일을 잃거나 미완성을 main에 커밋하면 안 됩니다.

변형: 새 미추적 메모가 추가되어 있다면 보관 방법과 검증 항목이 어떻게 달라지나요?

복합 문제 C · 충돌을 취소할까, 해결할까?

delete-conflict 모드를 생성합니다. A는 문서를 수정했고 B는 제거했습니다. 첫 시도에서는 요구사항이 확정되지 않았으므로 병합을 안전하게 중단하세요. 다시 병합한 뒤 “문서는 유지하되 최신 안내를 반영한다”라는 합의에 따라 해결하세요.

파일 내용, 미해결 index 항목, commit 부모와 status를 각각 확인합니다. 다른 사람이 변경한 의도를 확인하지 않고 한쪽을 버리면 통과할 수 없습니다.

공통 통과 기준

확인관찰 가능한 결과
진단현재 branch, staged/unstaged, 공유 여부를 근거로 설명
보존보존 대상 파일과 커밋을 먼저 식별
선택선택한 방법과 피한 방법의 영향 설명
복구본인·동료 변경 손실 없이 목표 달성
검증파일 내용과 이력, 실제 코드인 경우 실행 결과 확인
안전비밀정보와 공유 이력 재작성은 중단·보고 판단

오류가 없어졌다는 말만으로는 통과하지 않습니다. 상태가 다른 세 문제에서 연속으로 독립 수행한 뒤 실제 프로젝트 첫 작업에서도 같은 기준을 확인합니다. 힌트가 필요하면 재실습하며 질문 자체를 실패로 취급하지 않습니다.

원격수업 운영

학생은 화면 공유로 현재 상태와 판단 이유를 1~2분 설명합니다. 강사는 대신 명령을 입력하지 않고 “무엇이 사라지면 안 되나?”, “어떤 출력이 성공을 증명하나?”를 질문합니다. 짝이 없으면 local remote 실습으로 기술 흐름을 연습하고, 실제 PR 리뷰는 강사와 교대로 진행합니다.

4시간 본 수업에서는 상태·브랜치·동기화·충돌의 대표 사례를 다룹니다. 이후 수업 시작마다 10~15분 복구 문제를 반복합니다. 어려운 복합 문제는 20~30분을 확보하며, 이 시간은 기존 4시간에 숨겨 넣지 않습니다.
