MODULE 04

2인 충돌을
합의하고 해결하기

같은 줄 충돌을 실제로 발생시키고, 양쪽 변경을 비교해 최종 결과를 합의하고 검증합니다.

2인 필수merge conflict합의 + 검증

문제 상황

두 사람이 같은 줄을 다르게 수정하면 Git은 어느 내용이 맞는지 결정할 수 없습니다. 충돌 해결은 표시 삭제가 아니라 팀이 최종 결과를 결정하는 과정입니다.

역할과 시작 상태

A 학생

feature/team-message-a에서 README의 팀 목표 한 줄을 수정합니다.

B 학생

feature/team-message-b에서 정확히 같은 줄을 다른 내용으로 수정합니다.

git switch main
git pull --no-rebase origin main
git switch -c feature/team-message-a
# B는 feature/team-message-b 사용

충돌 만들기

  1. A가 수정, 커밋, push, PR 병합을 완료합니다.
  2. B가 자신의 변경을 먼저 커밋합니다.
  3. B가 최신 main을 가져와 feature에 병합합니다.
git fetch origin
git switch feature/team-message-b
git merge origin/main

반드시 보존

상태와 표시 해석

git status
git diff
# README 안에서 다음 세 표시를 찾는다
# <<<<<<<
# =======
# >>>>>>>
확인학생 설명
ours현재 체크아웃한 B 브랜치 쪽 내용
theirs병합하려는 origin/main 쪽 내용
최종 결과둘 중 하나 또는 두 내용을 조합해 팀이 결정

주의

ours를 항상 내 코드, theirs를 항상 상대 코드로 외우지 않습니다. 현재 브랜치와 병합 방향에 따라 의미가 달라집니다.

합의·해결·검증

  1. A와 B가 최종 팀 목표 문장을 합의합니다.
  2. 충돌 표시 세 종류를 모두 제거합니다.
  3. 파일을 stage하고 해결 커밋을 만듭니다.
  4. Java 실행과 충돌 표시 검색으로 검증합니다.
git add README.md
git status
git commit -m "merge: resolve team goal conflict"
git grep -n -e '<<<<<<<' -e '=======' -e '>>>>>>>' -- .
javac src/HelloTeam.java
java -cp src HelloTeam
git status

중단이 필요한 경우

해결 방향이 틀렸거나 병합을 시작하면 안 되는 브랜치였다면 변경을 더 만들기 전에 상태를 공유합니다. 병합 전 상태로 돌아가야 한다는 팀 합의가 있을 때만 다음을 사용합니다.

git merge --abort
git status

merge --abort가 실패할 수 있으므로 병합 전 미커밋 변경을 남기지 않는 것이 중요합니다.

제출 증거와 Explain Gate

증거PASS
충돌 오류 원문파일과 원인 식별
충돌 표시 화면ours/theirs를 현재 병합 방향으로 설명
합의 내용어느 변경을 왜 남겼는지 기록
해결 커밋표시 없음, 실행 성공, clean 상태

모듈 완료 확인

실제 PASS는 제출 증거와 설명 확인으로 판정합니다.
