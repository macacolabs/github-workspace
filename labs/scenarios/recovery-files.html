복구·파일·보안 상황

공유된 잘못된 commit 취소

git show <commit-hash>
git revert <commit-hash>
# 프로젝트 테스트
git status

공유 이력을 이동하지 않고 반대 변경을 새 commit으로 남깁니다.

commit 또는 branch 분실

git reflog
git show <found-hash>
git switch -c rescue/recovered-work <found-hash>

reset보다 rescue branch로 먼저 보존합니다.

stash 충돌 우려

git stash list
git stash show -p stash@{0}
git stash apply stash@{0}
git status

apply로 목록을 유지하고 완전히 복구된 뒤 drop합니다. untracked 파일은 기본 stash에 포함되지 않습니다.

비밀정보 commit/push

  1. 추가 push를 중단합니다.
  2. 키·토큰을 즉시 폐기하고 교체합니다.
  3. 관리자에게 노출 범위를 보고합니다.
  4. 새 비밀은 저장소 밖으로 이동합니다.
  5. 관리자가 이력 정리와 재동기화를 결정합니다.

파일 삭제 commit만으로 노출된 값이 안전해지지 않습니다.

대용량 파일 push 거절

산출물이면 제외합니다. 제품 자산이면 팀 승인 후 Git LFS와 용량 정책을 정합니다.

모든 줄이 변경 표시

줄바꿈 차이인지 확인하고 팀 규칙을 .gitattributes로 고정합니다. 정규화 commit은 기능 변경과 분리합니다.

* text=auto
*.sh text eol=lf
*.bat text eol=crlf

대소문자 rename 미반영

git mv User.java User.tmp
git mv User.tmp user.java
git status

Linux CI에서 import와 빌드를 확인합니다.

ignore인데 추적됨

git ls-files path/to/file
git rm --cached path/to/file
git status

로컬 파일은 남기고 추적에서 제외합니다.

혼자 진행하지 않는 경계

  • 공유 branch history 재작성
  • 원격 branch force push·삭제
  • 비밀정보 외부 노출
  • 모든 팀원의 clone에 영향을 주는 대규모 이력 정리
