PR과 팀 협업 상황

PR base 오류

base와 compare를 확인합니다. base 변경 뒤 Files changed와 commit 전체를 다시 보고, 이상하면 올바른 base에서 PR을 새로 만듭니다.

관련 없는 commit 혼입

git fetch origin
git log --oneline origin/main..HEAD
git diff --stat origin/main...HEAD

깨끗한 branch에서 필요한 commit만 옮깁니다.

PR 뒤처짐 또는 conflict

로컬에서 base를 통합하고 충돌 해결·테스트 후 같은 PR branch에 push합니다. 전체 diff를 다시 봅니다.

Changes requested

  1. 요청 의도를 확인합니다.
  2. 같은 branch에 작은 수정 commit을 추가합니다.
  3. 테스트 결과와 변경을 알립니다.
  4. 코드와 checks 뒤 대화를 Resolve합니다.

보호 규칙/check 차단

실패 check 상세와 필요한 승인 수를 봅니다. 원인을 수정하거나 승인을 기다립니다. 관리자 우회를 요구하지 않습니다.

같은 feature branch를 두 명이 사용

학생별 branch를 사용하고 PR에서 통합합니다. 공동 branch라면 push 전 fetch·소통·담당 파일 규칙이 필요합니다.

중단 상대 commit 위에 force push하지 않습니다.

PR의 5문장

  1. 왜 바꿨는가?
  2. 무엇을 바꿨는가?
  3. 어떻게 확인했는가?
  4. 집중해서 볼 곳은?
  5. 남은 위험은?
