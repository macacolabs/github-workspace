MODULE 02 · 2시간차

기능 브랜치에서
안전하게 작업하기

최신 main에서 기능 브랜치를 만들고, 브랜치 포인터와 커밋 차이를 증거로 확인합니다.

개인 실습switchcommit graph

명령 전에 내부 상태 읽기

브랜치는 폴더가 아니라 커밋을 가리키는 참조입니다. 일반적인 HEAD는 현재 브랜치를 가리키고, commit하면 그 브랜치가 새 커밋으로 이동합니다. 다른 브랜치는 자동으로 이동하지 않습니다.

상세 원리·복구 방법 선택·검증 연습 →

문제 상황

모든 학생이 main에서 직접 작업하면 미완성 코드와 충돌이 즉시 공유됩니다. 기능별 작업 공간을 만들고 main과 분리된 이력을 확인합니다.

시작 상태 확인

git status
git branch --show-current
git log --oneline --decorate -3

예측

새 브랜치를 만들면 기존 파일과 커밋은 사라질까요? HEAD는 어디를 가리킬까요?

미션 1 — 기능 브랜치

  1. 현재 main이 clean인지 확인합니다.
  2. 자기 이름을 사용한 기능 브랜치를 만듭니다.
  3. members/이름.md를 작성하고 커밋합니다.
  4. HelloTeam.java를 별도 커밋으로 수정합니다.
git switch main
git status
git switch -c feature/이름-profile
git branch --show-current
git add members/이름.md
git commit -m "feat: add 이름 profile"
git add src/HelloTeam.java
git commit -m "feat: include 이름 in greeting"
git log --oneline --graph --decorate --all

미션 2 — 브랜치 차이 읽기

git diff main..HEAD
git log --oneline main..HEAD
git switch main
git log --oneline --decorate --all

Checkpoint

main으로 이동했을 때 자기 소개 파일이 보이지 않아도 삭제된 것이 아닙니다. feature 브랜치 커밋에 존재합니다.

확인 결과

main에는 없고 feature에만 있는 커밋 해시 두 개를 찾아 말합니다.

실패 재현 — 변경 중 브랜치 전환

가정이 아니라 반드시 전환이 거절되는 별도 환경에서 연습합니다. 먼저 현재 프로젝트 위치를 확인해 두세요.

Get-Location
# 수업자료 저장소 루트에서 실행
python scripts/recovery_lab.py branch
# 출력된 Set-Location 명령으로 새 연습 폴더 이동
git status
git switch main

README의 미커밋 내용이 main 전환으로 덮일 수 있어 거절됩니다. 변경이 남아 있는지 status와 파일 내용으로 확인합니다. 임시 보관 절차로 작업을 보존한 뒤 전환·복원합니다.

연습 후 앞에서 확인한 원래 프로젝트 경로로 돌아가 아래 병합 실습을 계속합니다. 연습 저장소를 실제 프로젝트로 착각하지 않습니다.

선택과 병합

미커밋 변경을 처리한 뒤 main으로 이동해 feature를 병합합니다. 병합 전 그래프와 병합 후 그래프를 비교합니다.

git status
git switch main
git merge feature/이름-profile
git log --oneline --graph --decorate --all
git status

실습 확인과 Explain Gate

확인할 결과PASS 기준
기능 브랜치명feature/작업 형태
브랜치 커밋 2개목적별 분리
병합 전후 그래프포인터 이동 설명
전환 시 관찰Git의 데이터 보호 조건 설명

말로 설명

  • 브랜치와 폴더 복사는 무엇이 다른가?
  • HEAD는 지금 무엇을 가리키는가?
  • main 직접 작업이 팀에 주는 위험은 무엇인가?

모듈 완료 확인

버튼은 자기 기록입니다. 실제 PASS는 위 실행 결과와 설명을 강사가 확인한 뒤 판정합니다.

완료 상태는 현재 브라우저에 저장됩니다.
