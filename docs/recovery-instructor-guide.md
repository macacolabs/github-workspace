# 판단·복구 수업 운영과 확인

## 시작 준비
학생 PC에는 Git과 텍스트 편집기만 필요하다. Windows 기본 PowerShell을 사용한다.
학생은 labs/recovery/git-markdown-practice.md의 명령으로 새 폴더와 문서를 직접 만든다.
재시작은 공통 준비부터 새 고유 폴더에서 수행하며 이전 폴더는 보존한다.
Python 스크립트는 강사용 회귀 검증 전용이며 학생 설치를 요구하지 않는다.
실제 프로젝트 폴더에 실험용 reset/init 명령을 복사하게 하지 않는다.

## 강사가 읽을 판단 기준
- staged: 커밋에는 README만, notes와 draft 보존. clean을 강요하지 않는다.
- branch: switch 거절 후 변경 유지. 보관 전후 내용이 일치해야 한다.
- committed: feature에 실수 커밋 보존, 미공유 main만 practice-base로 이동.
- remote: HEAD와 origin/main 0/0, 두 파일 보존, notes는 미커밋으로 남음.
- conflict: abort 시 원래 tip과 clean, 재병합 후 두 부모·합의 내용 확인.
- delete-conflict: 유지/삭제의 근거부터 듣고 선택 결과 검사.
- stash: 미추적 draft까지 복원, 내용 검증 전 drop하지 않음.
- lost: 실제 reflog 해시를 찾아 show 후 rescue 이름으로 보존.
- shared: 원래 커밋이 조상으로 남고 반대 커밋 추가.

## 힌트 수준
새 진단 카드의 준비·원인·판정은 [독립 진단 운영안](independent-practice-instructor.md)을 따른다.
학생 페이지에는 진행자 문서를 직접 연결하지 않는다. 준비를 본 학생은 독립 PASS로 판정하지 않는다.

1단계는 모든 절차를 읽어도 된다.
2단계는 확인 명령만 제공한다.
3단계는 요구사항만 준다.
힌트 사용은 기록물 제출 대신 강사가 관찰하며 같은 조건 재암기가 아닌 변형 문제로 다시 확인한다.

## 독립 수행 확인
상태 진단 / 보존 대상 / 선택 근거 / 결과 내용 / 이력 / 중단 경계를 모두 설명해야 한다.
서로 다른 세 조건을 통과하고 실제 프로젝트에서 같은 습관을 확인한다.
force push나 비밀정보 공유를 빠른 해결로 칭찬하지 않는다.

## 원격수업
짝이 없는 학생은 bare remote로 통합 흐름까지 수행한다.
PR 리뷰·승인은 강사 또는 동료와 진행하며, 혼자 PR 생성한 것을 협업 완료로 판정하지 않는다.
화면 공유 전 토큰·이메일 등 개인정보 노출 여부를 확인한다.
학생의 오류를 대신 고치기보다 첫 확인 명령과 보존 대상을 질문한다.

## 실제 프로젝트 운영 규칙
main 직접 push 금지, 기능별 branch, 목적별 작은 커밋, PR 리뷰 후 merge commit 방식.
실험용 main push는 로컬 bare remote 또는 수업 전용 저장소에서만 예외.
squash/rebase를 쓰는 팀은 branch 정리와 이력 해석을 별도 설명한다.
권한·검증 check·보안 사고 처리는 책임자와 협의한다.
