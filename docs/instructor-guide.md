# Git & GitHub 프로젝트 투입 과정 강사용 운영안

## 운영 원칙

- 설명 직후 15~20분 학생 실습을 배치한다.
- 학생은 명령 실행 전에 예상 상태를 말한다.
- 완료 버튼이 아니라 Git 이력, 브랜치, 오류 메시지, PR로 확인한다.
- 강사는 오류를 대신 해결하지 않고 확인 명령 선택부터 묻는다.
- reset --hard, clean -fd, force push는 강사 승인 없는 해결책으로 제시하지 않는다.

## 사전 준비

- 학생 2명당 GitHub 협업 저장소 1개
- 두 학생 모두 collaborator 권한
- Windows용 Git과 Git Credential Manager 설치
- GitHub 계정 로그인과 2FA 준비
- starter 폴더 배포
- 충돌 실습 짝 편성
- 인터넷 장애 시 사용할 로컬 bare remote 예비 시나리오

## 시간별 체크포인트

### 1시간차

status, diff, diff --staged를 구분하고 README와 Java 변경을 분리해 커밋한다. 비밀정보 값을 실제로 만들거나 공유하지 않는다.

### 2시간차

switch -c로 기능 브랜치를 만들고 커밋 그래프에서 main과 feature 위치를 설명한다.

### 3시간차

PR에 목적, 변경, 검증, 리뷰어를 기록한다. 리뷰는 한 줄을 지정하고 이유와 기대 결과를 적는다. 학생은 새 커밋으로 반영한다.

### 4시간차

두 학생이 README의 같은 줄을 다르게 수정한다. 먼저 병합된 변경을 다른 학생이 반영해 충돌을 만들고, status 확인, 최종 내용 합의, add, commit, 실행 검증 순서로 해결한다.

## 반복 실습 기록

Java 수업과 프로젝트에서 매회 다음 네 항목을 기록한다.

- 시작 브랜치와 최신화 증거
- 이번 작업 커밋
- PR 또는 리뷰
- 발생한 문제와 확인 명령

3회 연속 독립 수행하면 적용 PASS로 전환한다.
