# 제3자 관점 검토 반영 상태

## 반영한 항목

- 원격 실습에 폴더·작업 상태·main 복귀 확인 추가. feature에서 main 전송하는 혼동 방지.
- 홈 카드·사이드바·다음 버튼의 원격 → PR → 충돌 순서 통일.
- Teaching Plan의 team.md 경로와 Markdown 검증 기준 수정.
- 240분 안에 준비 15분, 휴식 20분, 확인·지연 대응 20분 확보. 심화 반복은 별도.
- D1 설정 문제를 push.default=nothing 기반 전송 대상 미지정 거절로 변경.
  자동 upstream 설정이 켜져도 동일하게 재현된다. upstream 오류의 해석도 학생 힌트에 유지.
- 중간 Git 실패를 검사하는 강사용 PowerShell 실행기 추가.
  명시한 예상 실패가 성공하거나 예상하지 않은 명령이 실패하면 즉시 테스트 중단.
- revert continue 실패는 빈 작업 메시지·빈 index·충돌 없음 확인 후에만 skip.
- 원격 D2/D3: 개인정보 없는 연습 저장소를 .git 포함 ZIP으로 전달.
  준비·전달·해시 확인·새 폴더 복원·재시작·독립 판정 절차 문서화.
- D1은 원격 경로 때문에 같은 ZIP 전달 대상에서 제외. 오류 카드와 안내형 실행으로 구분.

## 검증과 한계

validate-course.ps1로 기존 실습과 새로운 회귀 검증을 실행한다.
ZIP 검증은 같은 Windows PC의 다른 폴더에서 포장·복원하고 D2/D3를 해결하는 검사다.
다른 PC·실제 수업 채널 전달, GitHub 계정 2개의 PR·승인·권한·수업 소요시간은 검증 대기다.
이를 로컬 테스트 PASS로 대체하지 않는다.

## 실제 수업 전 최종 리허설 체크리스트

1. 진행자가 D2/D3를 포장하고 수업 채널로 전달. 학생 역할의 다른 PC에서 해시·.git·상태 확인.
2. 학생이 준비 내용을 보지 않고 진단·복구하고 작업 보존을 설명. 도움 수준 기록.
3. 실제 수업 전용 GitHub 저장소를 두 계정으로 clone. 학생별 권한과 인증 확인.
4. 첫 커밋 → branch → push → PR → 리뷰 수정 → 동료 main 변경 → 재통합 → 재리뷰 → merge.
5. 둘 다 main 최신화, 문서·이력 일치, 미완성 작업·불필요한 파일 미포함 확인.
6. 구간별 시간과 막힌 지점을 기록. 240분 초과 시 심화로 넘길 구간 확정.

사용자 승인 없이 main 병합하지 않는다. 이 보고서는 수업 전체 승인서가 아니다.
